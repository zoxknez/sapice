# AGENTS.md

## Project mission

Šapice is a deterministic SR/EN web application for predefined winter shelter plans for cats and dogs.

It is **not** an AI design generator. Do not add runtime LLM/AI generation, free-form shelter generation or opaque recommendation logic.

## Non-negotiable invariants

1. Canonical shelter geometry lives in `src/data/models.ts` and reusable construction assemblies.
2. Derived values must come from compiler/engineering functions, not duplicated literals in UI components.
3. A source, geometry-derived value, calculation and assumption are different provenance classes. Never blur them.
4. Never promote validation status without evidence for the preceding stage.
5. Software tests are not physical prototype or field-test evidence.
6. Every compiled plan is identified by model version + compiler version + plan fingerprint. Persisted build/prototype state must not silently cross plan fingerprints.
7. Heated models may only accommodate purpose-built animal-heating products. Do not add DIY mains-heater instructions.
8. Ventilation provision zones are coordination geometry, not universal vent-size requirements.
9. The service roof must preserve the front-high / rear-runoff weathering invariant unless the roof system is deliberately redesigned and revalidated.
10. Do not publish a “safe to X °C” claim from the current thermal engine.
11. Do not invent current material prices. User prices or sourced dated market prices only.
12. SR and EN routes/content must remain functionally equivalent.
13. Accessibility, offline behavior and print/PDF output are part of the product, not optional polish.

## Validation ladder

```text
DATA_VALIDATED
GEOMETRY_VALIDATED
ENGINEERING_REVIEWED
PROTOTYPE_BUILT
FIELD_TESTED
```

Moving upward requires explicit evidence. Never infer a higher state from code completion.

## Engineering workflow

When editing a model:

1. update canonical model data
2. compile derived geometry
3. validate source IDs and assemblies
4. validate cut-part stock fit
5. validate finder behavior and passive/heated catalog coverage
6. inspect 3D, technical sketch, BOM/export and plan fingerprint consistency
7. validate roof runoff, ventilation provision and heating provision invariants
8. run typecheck, lint, unit tests, production build and E2E smoke tests
9. only then consider validation-state changes
