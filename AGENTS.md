# AGENTS.md

## Project mission

Šapice is a deterministic SR/EN web application for predefined winter shelter plans for cats and dogs.

It is **not** an AI design generator. Do not add runtime LLM/AI generation, free-form shelter generation or opaque recommendation logic.

## Non-negotiable invariants

1. Canonical shelter geometry lives in `src/data/models.ts` and reusable construction assemblies.
2. Derived values must come from compiler/engineering functions, not duplicated literals in UI components.
3. A source, geometry-derived value, calculation and assumption are different provenance classes. Never blur them.
4. Never promote validation status without evidence for the preceding stage.
5. Software tests are not physical prototype or field-test evidence.
6. Heated models may only accommodate purpose-built animal-heating products. Do not add DIY mains-heater instructions.
7. Do not publish a “safe to X °C” claim from the current thermal engine.
8. Do not invent current material prices. User prices or sourced dated market prices only.
9. SR and EN routes/content must remain functionally equivalent.
10. Accessibility and print/PDF output are part of the product, not optional polish.

## Validation ladder

```text
DATA_VALIDATED
GEOMETRY_VALIDATED
ENGINEERING_REVIEWED
PROTOTYPE_BUILT
FIELD_TESTED
```

Moving upward requires explicit evidence. Never infer a higher state from code completion.

## Engineering workflow

When editing a model:

1. update canonical model data
2. compile derived geometry
3. validate source IDs and assemblies
4. validate cut-part stock fit
5. validate finder behavior
6. inspect 3D and technical sketch consistency
7. run typecheck, lint, unit tests and production build
8. only then consider validation-state changes
